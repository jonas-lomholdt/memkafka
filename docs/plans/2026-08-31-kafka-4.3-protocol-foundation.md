# Kafka 4.3 Protocol Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate MemKafka's wire types from Apache Kafka 4.3.1 and return Kafka-shaped `UNSUPPORTED_VERSION` responses without advertising or implementing any new broker behavior.

**Architecture:** Keep the upstream-shaped `kafka-protocol` fork as an excluded nested workspace and consume it through a root path dependency. Split fixed-prefix/header/body decoding, pure capability routing, typed error construction, supported dispatch, and connection lifetime into separate modules. Only the router can create the opaque token accepted by `Dispatcher`, making rejected-state mutation structurally impossible.

**Tech Stack:** Rust 1.98 / edition 2024 for MemKafka, vendored `kafka-protocol` 0.18.0 fork / edition 2021, Apache Kafka 4.3.1 protocol JSON, Bash, Java 25 with `kafka-clients` 4.3.1, Maven, Docker, GitHub Actions.

**Spec:** [`docs/2026-08-30-kafka-4.3-protocol-foundation-design.md`](../2026-08-30-kafka-4.3-protocol-foundation-design.md)

## Global Constraints

- Work on the current `main` branch as already authorized. Do not create a worktree or another planning directory.

In `codec.rs` introduce:

```rust
pub struct RequestPrefix {
    pub raw_api_key: i16,
    pub api_version: i16,
    pub correlation_id: i32,
}

pub enum DecodedFrame {
    Request(DecodedRequest),
    UnsupportedApiVersions {
        header: RequestHeader,
        requested_version: i16,
    },
}

pub enum RequestDecodeError {
    TruncatedPrefix,
    UnknownApiKey { prefix: RequestPrefix },
    VersionOutOfSchema { prefix: RequestPrefix, api_key: ApiKey },
    Malformed {
        prefix: Option<RequestPrefix>,
        api_key: Option<ApiKey>,

}
```

Implement `Display` and `Error` manually; do not add another error crate. `DecodeStage` is `Header`, `Body`, or `TrailingBytes`.

Decode order:

```text

convert raw key
if non-ApiVersions and version is outside ApiKey::valid_versions(): structured close error
decode RequestHeader using api_key.request_header_version(requested_version)
if ApiVersions is outside its valid range: return UnsupportedApiVersions
decode RequestKind and reject trailing bytes
```

Do not use `ApiKey::valid_versions()` as support policy; this check is only schema availability.

`request_router.rs` owns:

```rust
pub(crate) struct SupportedRequest<'a>(&'a DecodedRequest);

pub(crate) struct ResponseEnvelope {
    pub(crate) api_key: ApiKey,
    pub(crate) encoding_version: i16,
    pub(crate) correlation_id: i32,
    pub(crate) body: ResponseKind,
}

pub(crate) enum Route<'a> {
    Dispatch(SupportedRequest<'a>),
    Respond(ResponseEnvelope),
    NoResponse,
}

pub(crate) enum RouteError {
    UnsupportedApi { api_key: ApiKey, version: i16, correlation_id: i32 },

}

```

`SupportedRequest` exposes read-only `header()`, `api_key()`, `body()`, and `expects_response()` accessors. `Dispatcher::dispatch` accepts `SupportedRequest<'_>`, not `DecodedRequest`. - [ ] Implement ordinary and special decisions.

- no capability -> `UnsupportedApi` close;
- capability supports version -> opaque dispatch token;

```text
Respond -> encode/write the envelope
NoResponse -> continue loop immediately
route close -> trace unsupported_api and close this connection
```
